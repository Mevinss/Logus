# Logus

**[Пройти четыре задания «Масштаб карты» с телефона](https://logus-five.vercel.app/practice)**

Практикум открывается без регистрации. После сдачи ученик видит баллы за три тестовых задания. После ошибки ученик может сразу пройти персональную разминку и сравнить баллы за навык до и после. Учитель проверяет письменное объяснение и подтверждает итог в журнале.

[Вход учителя и ученика](https://logus-five.vercel.app/)

## Идея

Logus помогает учителю понять, что группе стоит повторить после урока. Ученики читают материал и отвечают с телефона. По ответам учитель выбирает конкретный навык и назначает короткую разминку тем, кому она нужна.

## Реализация

Приложение на Next.js и TypeScript работает по публичной ссылке и поддерживает локальный запуск в школьной сети. Сервер извлекает текст из PDF, передаёт выбранные страницы ИИ и хранит версии уроков, ответы и оценки в SQLite.

## Чем отличается Logus

- У каждого вопроса есть цитата и ссылка на страницу PDF или абзац. Перед публикацией учитель может проверить источник и исправить задание.
- В аналитике видно, сколько учеников выбрали конкретный ошибочный вариант. Из этого показателя можно открыть работы и назначить разминку.
- У разминки своя оценка. В журнале рядом остаётся исходная попытка, поэтому учитель и ученик видят результат повторения.

В редакторе можно заменить один вопрос с сохранением его навыка, типа, баллов и источника. В новых тестах результаты по умолчанию скрыты до публикации учителем. Старые проведения сохраняют прежний режим немедленного показа. В аналитике процент верных ответов считается по проверенным работам.

## Тесты, расписание и настройки

Редактор принимает PDF с текстовым слоем, DOCX и TXT, в том числе несколько файлов. Выберите источники, количество вопросов (1–20), количество открытых вопросов, язык, сложность, тему и пожелания. Генерация создаёт черновик: можно исправить вопросы и объяснения, изменить порядок, добавить вопросы вручную или с помощью ИИ и открыть предварительный просмотр. Сканированный PDF требует внешнего OCR. Черновик без проведений можно удалить; проведённый тест архивируется с сохранением работ.

Выбор страниц ограничивает текст заданий и поиска, но ссылка на оригинал PDF открывает весь файл. Для выдачи только части документа загрузите отдельный PDF с разрешёнными страницами.

В настройках теста задаются время открытия, срок сдачи и длительность (1–240 минут). Отсчёт начинается на сервере после нажатия учеником кнопки начала; обновление страницы не сбрасывает таймер. По истечении времени сервер завершает работу по сохранённым ответам при следующем обращении. Учитель проверяет открытые ответы и нажимает «Опубликовать результаты» в «Группы → Занятия». Публикуются проверенные работы на этот момент; для поздних сдач нужно снова нажать кнопку. После публикации ученик видит баллы, объяснения и разбор тем. Для тренировок можно выбрать немедленный показ результатов.

«Расписание» поддерживает неделю, месяц и список, повторения по дням недели, изменение одного события или будущей части серии, материал и опубликованный тест. События класса доступны его ученикам. «Добавить в Google Calendar» открывает создание копии одного события; `.ics` позволяет импортировать расписание. Это экспорт, а не двусторонняя синхронизация: изменения в Logus не обновляют ранее импортированные копии.

В профиле сохраняются имя, язык интерфейса (қазақша / русский / English), светлая, тёмная или системная тема и часовой пояс. Учитель может сменить пароль с проверкой текущего. Язык материалов и вопросов выбирается отдельно от интерфейса. Интерфейс учитывает системную настройку уменьшения анимации.

## Первый запуск в PowerShell

Требуется Node.js 24 LTS и npm. В каталоге репозитория выполните:

```powershell
npm ci
if (!(Test-Path .env.local)) { Copy-Item .env.example .env.local }
npm run db:setup
npm run build
npm start
```

При первом запуске `db:setup` создаёт учителя `teacher@logus.local`. Случайный пароль сохраняется в `data\teacher-login.txt`. Можно заранее задать `TEACHER_EMAIL` и `TEACHER_PASSWORD` в `.env.local`. Повторный запуск сохраняет существующую учётную запись. Команда `npm run demo` добавляет практикум по масштабу карты с четырьмя заданиями для работы без ключа ИИ.

## Вход и проведение

Для демонстрации с отдельным учителем выполните `npm run demo:class`. Команда добавляет класс «7А · Демо-класс», трёх учеников и готовые уроки по математике, физике и Python с заданиями и расписанием. Данные входа находятся в `data/demo-access-local.txt`; пароль и приглашения не попадают в Git. Повторный запуск сохраняет выполненные работы. Учителя и учеников открывайте в разных профилях браузера или приватных окнах. В демо-тестах включены таймер 15 минут и публикация результатов учителем.

Для существующего Vercel Blob оператор может выполнить `node --env-file=.env.vercel-logus scripts/demo-class.mjs --cloud`, задав `LOGUS_DEMO_BASE_URL` равным адресу сайта. Команда сначала сохраняет резервную копию облачной базы в `backups`, затем добавляет демо-данные с проверкой версии базы. Файл `data/demo-access-online.txt` содержит ссылки для облака. Используйте тот же `data/demo-access.json` при повторном запуске; существующие пароли автоматически не сбрасываются.

Откройте http://localhost:3000 на ноутбуке. Для следующего запуска достаточно `npm start`. Команда печатает адрес учителя и адрес для телефона, отдавая предпочтение Wi-Fi, и слушает `0.0.0.0`. Телефон должен иметь доступ к ноутбуку по указанному порту. Если сеть содержит VPN или несколько адаптеров, задайте в `.env.local` адрес вида `PUBLIC_BASE_URL=http://192.168.1.20:3000` и перезапустите приложение. Порт можно задать через `PORT`. Если Windows запросит сетевой доступ, разрешите его для используемой частной сети.

1. В «Группах» создайте группу, добавьте ученика по имени или псевдониму и скопируйте его индивидуальное приглашение. На главной учитель выбирает «Я учитель» и входит по почте и паролю. Ученик выбирает «Я ученик», вставляет приглашение и нажимает «Войти по приглашению». Эту же ссылку можно открыть напрямую с телефона.
2. В «Моих уроках» создайте черновик. Загрузите PDF с текстовым слоем или вставьте текст, разделив абзацы пустыми строками. Выберите страницы, подготовьте задания и проверьте цитаты через «Открыть источник».
3. Опубликуйте урок для группы. Ссылку на занятие могут использовать уже вошедшие ученики. Изменения черновика попадут только в следующие проведения.
4. После сдачи проверьте открытые ответы в журнале. Из аналитики откройте проблемный вопрос, подготовьте разминку и выберите получателей. Разминка получает отдельную запись в журнале.

## Работа с классом

В «Группы → Состав → Импорт класса» вставьте один столбец из Excel. Сверьте список перед добавлением. Повторный импорт пропустит совпадающие имена. Для тёзок укажите разные подписи. Распечатайте личные QR-карточки и вручите каждому его карточку. Если карточка потеряна, откройте приглашение ученика и нажмите «Заменить приглашение». Старая ссылка и сеансы ученика перестанут работать, оценки сохранятся.

Откройте активное занятие с экрана «Сегодня» или выберите проведение на вкладке «Урок идёт». Список обновляется каждые пять секунд. «Открыли урок» означает, что аккаунт открыл материал хотя бы раз. Покинувший вкладку ученик продолжает учитываться. Ниже можно выбрать открытый вопрос, оценить ответ и перейти к следующему ученику. Если вопросов несколько, итог появится после оценки всех ответов. В «Журнал → Скачать Excel» выберите занятие или период. Числовые оценки, статусы и отдельные проведения сохраняются в XLSX.

### Несколько преподавателей

Создатель класса отвечает за список учеников и приглашения. Для регистрации ещё одного преподавателя оператор сервера может выполнить команду в отдельном окне PowerShell:

```powershell
$env:TEACHER_EMAIL = "physics@school.example"
$env:TEACHER_PASSWORD = ""
npm run db:setup
```

Команда укажет файл с паролем нового учителя. Передайте данные входа этому учителю. Владелец класса в «Состав → Преподаватели класса» указывает зарегистрированную почту и предмет. Предметник назначает работы тому же составу и видит результаты собственных занятий. Ученик пользуется одной личной ссылкой. Через «Передать копию урока» коллега получает отдельный черновик с PDF, вопросами и критериями.

### Резервная копия и восстановление

Для локального сервера выполните `npm run db:backup`. Команда снимет согласованную копию SQLite и скопирует относящиеся к ней PDF в отдельный каталог внутри `backups`. Команда `npm run db:backup -- E:\LogusBackup` сохранит копию на выбранном носителе. Каталог содержит учебные данные и действующие приглашения, храните его с ограниченным доступом.

Чтобы проверить восстановление, скопируйте каталог снимка в новую папку и запустите второй локальный сервер из каталога проекта:

```powershell
$copy = Get-ChildItem .\backups -Directory -Filter "logus-*" | Sort-Object Name -Descending | Select-Object -First 1
$restore = Join-Path $env:TEMP ("logus-restore-" + [guid]::NewGuid())
Copy-Item -LiteralPath $copy.FullName -Destination $restore -Recurse
$env:LOGUS_DATA_DIR = $restore
$env:PORT = "3100"
$env:PUBLIC_BASE_URL = "http://localhost:3100"
npm start
```

Откройте http://localhost:3100, войдите своим паролем, сверьте журнал и откройте PDF опубликованного урока. После проверки остановите второй сервер и закройте это окно PowerShell.

### Пилот в школе

Проведите по одному уроку у двух преподавателей, второй преподаватель готовит занятие самостоятельно из переданной копии. Для каждого запишите предмет, размер класса, минуты от открытия материала до публикации, число учеников, вошедших без помощи, и минуты на проверку сданных работ. Попросите назвать одно действие, которое пришлось объяснять. Эти данные нужны для выбора следующей доработки.

## ИИ и данные

В `.env.local` настройте серверные `OPENAI_API_KEY`, `AI_MODEL` и при необходимости `AI_BASE_URL`. Адаптер вызывает совместимый с OpenAI маршрут `/chat/completions` и ожидает поддержку JSON-ответов. После изменения настроек перезапустите сервер. Ключ не передаётся браузеру. Без ключа работают ручные вопросы, расписание и проверка.

RAG реализован локальным полнотекстовым поиском SQLite FTS5: материал разбивается на фрагменты, поиск ограничен выбранными источниками текущего учителя. В запрос передаётся не более 16 000 символов контекста. Отдельный API эмбеддингов не нужен. Для генерации вопросов и подсказки проверки нужен доступ к LLM через настроенный API. В подсказку проверки передаются вопрос, критерий и ответ конкретного ученика.

Повтор одинакового запроса использует кеш по учителю, контексту, параметрам, модели и адресу провайдера. Одновременные одинаковые запросы в одном процессе объединяются. Лимит — 6 новых запросов в минуту на учителя; `AI_MAX_OUTPUT_TOKENS` ограничивает ответ (по умолчанию 6000, диапазон 1000–12000). Таблица `ai_usage` хранит статус и токены, если провайдер их возвращает. Объяснения сохраняются с вопросами и повторно используются для учеников; обычные графики и подсчёт ошибок не вызывают LLM. На нескольких облачных экземплярах для строгого общего лимита и дедупликации потребуется общее атомарное хранилище. Кеш и лимиты не заменяют денежный лимит у провайдера.

Новые таблицы профилей, расписания, таймера, публикаций и поиска создаются автоматически при открытии базы. Существующие уроки и работы не переписываются. Перед обновлением используйте резервную копию; восстановление описано выше.

`data/logus.sqlite` хранит пользователей, сессии, версии работ, ответы и результаты. Оригиналы PDF находятся в `data/files/`. Чтобы перенести пилот, остановите сервер и скопируйте каталог `data` целиком. Для отдельной базы задайте `LOGUS_DATA_DIR`. База, пароли, приглашения и файлы учащихся исключены из Git.

## Развёртывание на Vercel

Проект использует Node.js 24 и отдельный приватный Vercel Blob в регионе Frankfurt. Подключите хранилище к Production. Для нового экземпляра подготовьте чистую SQLite командой `npm run db:setup`, затем выполните `npm run demo` с `LOGUS_PUBLIC_PRACTICE=1`. Загрузите эту папку командой `node --env-file=.env.local scripts/seed-cloud.mjs data`, указав в файле окружения серверный BLOB_READ_WRITE_TOKEN.

В облаке журнал сохраняется между публикациями. Каждая запись проверяет версию базы. При конфликте сервер просит повторить действие. Этот способ рассчитан на пилот с небольшой группой. Для PDF в Vercel действует ограничение 4 МБ на файл.

## Показ жюри за 3–4 минуты

Заранее создайте группу с двумя учениками и откройте личное приглашение первого на телефоне. Подготовьте небольшой PDF с текстовым слоем. Если ключ ИИ не настроен, подготовьте черновик с ручными вопросами и покажите его как ручную работу.

1. **0:00–1:00, ноутбук.** Покажите материал, выбранную страницу и два вопроса (закрытый и открытый). Откройте источник вопроса, исправьте формулировку и назначьте урок группе.
2. **1:00–2:00, телефон.** Откройте занятие, выберите неверный вариант, обновите страницу и покажите сохранённый ответ. Введите короткое объяснение и сдайте работу.
3. **2:00–3:00, ноутбук.** В журнале откройте «Ожидает проверки», оцените объяснение и подтвердите итог. Для теста с ручной публикацией откройте «Группы → Занятия → Опубликовать результаты». Обновите результат на телефоне и сравните баллы.
4. **3:00–4:00.** В аналитике откройте ошибочный вариант, назначьте разминку первому ученику и пройдите её с телефона. В истории покажите рядом две оценки. Второму ученику разминка не назначена.
